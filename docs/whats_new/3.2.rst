****************************
What's New in Photutils 3.2?
****************************

Here we highlight some of the new functionality of the 3.2 release.
In addition to these changes, Photutils 3.2 includes several
smaller improvements and bug fixes, which are described in the full
:ref:`changelog`.

.. contents::
   :local:
   :depth: 2


Source Masks from the Moran's I Statistic
=========================================

The new `~photutils.background.make_morans_i_mask`
function makes a source mask from the `Moran's I
<https://en.wikipedia.org/wiki/Moran%27s_I>`_ spatial autocorrelation
statistic, which measures how strongly each pixel is correlated
with its neighbors within a small patch of the image. Background
noise gives a low value, while sources, including their faint
outer regions, give a high value. The statistic does not depend
on the background level or on the amplitude of the noise, so the
mask can be made before the background is known and then input to
`~photutils.background.Background2D`::

    >>> from photutils.background import Background2D, make_morans_i_mask
    >>> from photutils.datasets import make_100gaussians_image
    >>> data = make_100gaussians_image()
    >>> mask = make_morans_i_mask(data)
    >>> bkg = Background2D(data, (50, 50), mask=mask, filter_size=(3, 3),
    ...                    exclude_percentile=50.0)

The threshold is set relative to the typical value of the statistic
in the image, so it adapts to images with correlated noise such as
resampled mosaics. The map of the statistic itself is available from the
new `~photutils.background.make_morans_i_map` function.

See :ref:`morans_i_mask` for more details.


Isophote Improvements
=====================

Fitting Improvements
--------------------

The elliptical isophote fits of `~photutils.isophote.Ellipse` are now
about 5 times faster, and about 70 times faster for masked images with
the ``'bilinear'`` integration mode. Nonfinite (NaN or infinity) image
values are now excluded from the fits, like masked pixels.

Several differences from the STSDAS ``ellipse`` task that
`photutils.isophote` is based on were also fixed. They include the
convergence criterion, the ``max_gradient_rel_err`` stopping criterion,
the radius where the local intensity gradient is measured, and the
starting geometry of the inward fits. Because of these fixes, the fitted
isophotes differ slightly from those of previous versions. The fits of
noisy images typically extend to larger semimajor axis lengths. See the
:ref:`changelog` for the complete list of fixes.

The default geometry of `~photutils.isophote.Ellipse`, used when
no ``geometry`` is input, now has an orientation of 0 degrees (the
semimajor axis along the x axis) instead of 90 degrees, and its
center is the center of the image instead of half a pixel away. The
``step`` keyword of :meth:`~photutils.isophote.Ellipse.fit_image`
and :meth:`~photutils.isophote.Ellipse.fit_isophote` now defaults
to the ``step`` of the input `~photutils.isophote.EllipseGeometry`,
like the ``linear_growth`` keyword, instead of
always replacing it with 0.1. The object centerer of
:meth:`~photutils.isophote.EllipseGeometry.find_center` now samples two
circles, as in the STSDAS task, and its default ``threshold`` is 1.0
instead of 0.1, so that it no longer finds an object in an image of pure
noise.

The fits are also less sensitive to the starting ellipse. Previously,
a starting ellipticity of about half of the galaxy ellipticity,
combined with a starting orientation that was off by more than about
15 degrees, made the fitted orientation oscillate between two values
without ever converging. This included the default geometry of
`~photutils.isophote.Ellipse` for galaxies with an ellipticity near 0.4.
A correction that reverses the correction that the previous iteration
made to the same ellipse parameter is now halved. This also keeps the
center and ellipticity corrections of noisy isophotes from oscillating
across the solution, so fewer isophotes end at the maximum number of
iterations (stop code 2) and the fits need fewer iterations.

The first isophote of a low surface brightness galaxy now fails much
less often, because the local gradient of the previous iteration is used
as a reference, as in the STSDAS task. If a fit still fails, the warning
now explains why. See :ref:`isophote-low-snr` for advice on fitting
images with a low signal-to-noise ratio.


Measurements on Fixed Ellipses
------------------------------

The new :meth:`~photutils.isophote.Ellipse.measure_isophotes` method
measures an image along a given set of ellipses without fitting them,
like the STSDAS ``ellipse`` task with an input ellipse table (the
``inellip`` parameter). A common use is to measure an image in a
second band along the isophotes fit to a reference image, so that both
intensity profiles are measured along the same elliptical paths (e.g.,
for a color profile). For two aligned images ``data1`` and ``data2``::

    >>> from photutils.isophote import Ellipse
    >>> isolist1 = Ellipse(data1).fit_image()
    >>> isolist2 = Ellipse(data2).measure_isophotes(isolist1)

The returned `~photutils.isophote.IsophoteList` has one isophote for
each input ellipse, with the same geometry. The input can also be a
sequence of `~photutils.isophote.EllipseGeometry` objects that define
the ellipses directly. See :ref:`isophote_fixed_ellipses` for more
details.


Limiting the Center Shift
-------------------------

:meth:`~photutils.isophote.Ellipse.fit_image` and
:meth:`~photutils.isophote.Ellipse.fit_isophote` have a
new ``max_center_shift`` keyword that limits how far the
fitted ellipse centers can move from the center of the input
`~photutils.isophote.EllipseGeometry`. In the outer, low
surface-brightness regions of a galaxy, a nearby star or companion
galaxy can pull the fitted centers away from the galaxy nucleus. Unlike
``fix_center``, the centers are still fitted within that distance. For
an image ``data`` of a galaxy centered near (256, 256)::

    >>> import astropy.units as u
    >>> from photutils.isophote import Ellipse, EllipseGeometry
    >>> geometry = EllipseGeometry(x0=256, y0=256, sma=20, ellipticity=0.2,
    ...                            orientation=0.2 * u.rad)
    >>> ellipse = Ellipse(data, geometry=geometry)
    >>> isolist = ellipse.fit_image(max_center_shift=2.0)

If a fit would move the center of an isophote farther than this
distance, the center is placed at this distance from the input center
and held there for the rest of that fit, while the ellipticity and
orientation continue to be fitted. The keyword limits the total shift
from the input center, which is different from the ``wander`` parameter
of the STSDAS ``ellipse`` task. See :ref:`isophote-center-limit` for
more details.


Tables and Model Images
-----------------------

The new :meth:`~photutils.isophote.IsophoteList.from_table` method
creates an `~photutils.isophote.IsophoteList` from a table. It is
the inverse of :meth:`~photutils.isophote.IsophoteList.to_table`,
so a list of isophotes can be saved to a file and loaded again. The
``sma``, ``x0``, ``y0``, ``ellipticity``, and ``orientation`` columns
are required, and the angle columns must have an angular unit::

    >>> from astropy.table import QTable
    >>> from photutils.isophote import Ellipse, IsophoteList
    >>> tbl = isolist.to_table(columns=isolist.properties)
    >>> tbl.write('isophotes.ecsv')
    >>> loaded = IsophoteList.from_table(QTable.read('isophotes.ecsv'))

The loaded isophotes have no sample, but they can be
used to make a model image or to measure an image with
:meth:`~photutils.isophote.Ellipse.measure_isophotes`.

The new :meth:`~photutils.isophote.IsophoteList.make_model_image`
method makes a model image from the isophotes. It replaces the
``build_ellipse_model`` function. In this example, ``data2`` is a
second image, aligned with ``data``, that is measured along the loaded
isophotes::

    >>> model = loaded.make_model_image(data.shape)
    >>> measured = Ellipse(data2).measure_isophotes(loaded)

`~photutils.isophote.IsophoteList` also has new ``properties``
and ``default_columns`` attributes, like those of
`~photutils.segmentation.SourceCatalog`. ``properties`` lists the
names of all the isophote properties, which are also the columns that
``to_table`` can return. See :doc:`../user_guide/isophote` for more
details.


Sigma Clipping
--------------

:meth:`~photutils.isophote.Ellipse.fit_image`,
:meth:`~photutils.isophote.Ellipse.fit_isophote`, and
:meth:`~photutils.isophote.Ellipse.measure_isophotes` have a new
``sigma_clip`` keyword that takes an `~astropy.stats.SigmaClip`
object, like the other Photutils tools. The intensities sampled along
each ellipse are sigma clipped, which removes stars, cosmic rays, and
defective pixels from the fit. The `~astropy.stats.SigmaClip` object
gives access to options that the isophote tools did not have, such
as clipping around the median, different lower and upper limits, and
clipping until convergence::

    >>> from astropy.stats import SigmaClip
    >>> from photutils.isophote import Ellipse
    >>> sigma_clip = SigmaClip(sigma_lower=3.0, sigma_upper=2.5,
    ...                        maxiters=5)
    >>> isolist = Ellipse(data).fit_image(sigma_clip=sigma_clip)

The default is `None`, which means no sigma clipping, as before. The
``sigma_clip`` keyword replaces the ``sclip`` and ``n_clip`` keywords
(see :ref:`whatsnew-3.2-isophote-sigma-clip`).


Apertures From Ellipses
-----------------------

`~photutils.isophote.EllipseGeometry` and `~photutils.isophote.Isophote`
have a new ``to_aperture`` method that returns the ellipse as an
`~photutils.aperture.EllipticalAperture`. It makes it easy to plot the
initial ellipse or the fitted isophotes on an image::

    >>> import astropy.units as u
    >>> from photutils.isophote import Ellipse, EllipseGeometry
    >>> geometry = EllipseGeometry(x0=75, y0=75, sma=20, ellipticity=0.5,
    ...                            orientation=20.0 * u.deg)
    >>> geometry.to_aperture().plot(color='white')
    >>> isolist = Ellipse(data, geometry=geometry).fit_image()
    >>> isolist.get_closest(40.0).to_aperture().plot(color='white')

See :doc:`../user_guide/isophote` for an example.


Central Pixel Classes
---------------------

The ``CentralEllipseSample``, ``CentralEllipseFitter``, and
``CentralPixel`` classes were removed. They were not part of the public
API, so they have no deprecation period. The central pixel is now a
regular `~photutils.isophote.Isophote` with an ``sma`` of zero, and
``isophote.sma == 0`` replaces ``isinstance(isophote, CentralPixel)``.


Source Tables as Input to ``extract_stars``
===========================================

The :func:`~photutils.psf.extract_stars` function now recognizes common
alternative names for the pixel position columns of its input catalogs,
such as ``x_centroid``, ``x_fit``, ``x_center``, and ``x_peak`` (and
the same for ``y``). The output tables of the star finders and of the
PSF photometry classes can therefore be input directly, without first
creating a table with ``x`` and ``y`` columns. For an image ``data``::

    >>> from photutils.detection import DAOStarFinder
    >>> from photutils.psf import extract_stars
    >>> finder = DAOStarFinder(threshold=100.0, fwhm=1.5)
    >>> sources = finder(data)
    >>> stars = extract_stars(data, sources, size=25)

The x and y columns must have the same suffix. If a catalog has more
than one pair of position columns, the fitted positions are used first.
:func:`~photutils.psf.extract_stars`, `~photutils.psf.PSFPhotometry`,
and `~photutils.psf.IterativePSFPhotometry` now search for the position
columns in the same priority order. See :ref:`build-epsf` for more
details.


Gridded PSF Models on Image Cutouts
===================================

The `~photutils.psf.GriddedPSFModel` class has a new
:meth:`~photutils.psf.GriddedPSFModel.make_cutout_model` method for PSF
photometry on a cutout of an image or on a detector subarray. A gridded
PSF model interpolates its grid of ePSFs at the detector position
of each source, so it cannot be used as is on a cutout, whose pixel
coordinates are offset from the detector coordinates. The new method
returns a model for the cutout, given the position of the cutout origin
in the full image. For a full-frame image ``data``, a gridded PSF model
``psf_model``, and a star finder ``finder``::

    >>> from photutils.psf import PSFPhotometry
    >>> xstart, ystart = 800, 500
    >>> cutout = data[ystart:ystart + 200, xstart:xstart + 200]
    >>> cutout_model = psf_model.make_cutout_model((xstart, ystart))
    >>> psfphot = PSFPhotometry(cutout_model, (5, 5), finder=finder,
    ...                         aperture_radius=4)
    >>> phot = psfphot(cutout)

The cutout model shares the ePSF grid data with the input model, so the
data are not copied. See :ref:`psf-gridded-cutout` for more details.

New Deprecations
----------------

ASDF Subpackage
^^^^^^^^^^^^^^^

The ASDF converters, extension, schemas, and manifests have moved to the
new ``photutils.asdf`` subpackage. Importing from the old locations
(``photutils.converters`` and ``photutils.extension``) is deprecated and
will be removed in version 4.0. Update your imports::

    # Old (deprecated)
    from photutils.converters import CircularApertureConverter

    # New
    from photutils.asdf.converters import CircularApertureConverter

Most users never import these modules directly, because ``asdf`` loads
the photutils extension automatically. The ASDF tags and schema URIs are
unchanged, so existing ASDF files remain readable.

Isophote API Names
^^^^^^^^^^^^^^^^^^

The names in the `photutils.isophote` API were made consistent.
The same quantity now has the same name as an attribute, a table
column, and a keyword, and the names follow the conventions of
the rest of Photutils (spelled-out words, ``n_`` for counts,
and ``_err`` for errors). Every old name still works with a
`~photutils.utils.exceptions.PhotutilsDeprecationWarning`, which names
the old name and its replacement, if there is one, and will be removed
in version 4.0. Names that were already deprecated in version 3.0 (e.g.,
``grad_error``, ``niter``) now point directly to the new names.

For example, code that fits an image and reads the results changes
from::

    # Old (deprecated)
    geometry = EllipseGeometry(x0, y0, 20.0, eps=0.2, pa=0.5)
    isolist = Ellipse(data, geometry=geometry).fit_image(maxsma=100.0,
                                                         linear=True)
    print(isolist.intens, isolist.eps, isolist.pa)
    tbl = isolist.to_table('main')
    model = build_ellipse_model(data.shape, isolist, fill=0.0)

to::

    # New
    geometry = EllipseGeometry(x0, y0, 20.0, ellipticity=0.2,
                               orientation=0.5 * u.rad)
    isolist = Ellipse(data, geometry=geometry).fit_image(
        max_sma=100.0, linear_growth=True)
    print(isolist.intensity, isolist.ellipticity, isolist.orientation)
    tbl = isolist.to_table()
    model = isolist.make_model_image(data.shape, fill_value=0.0)

The ``orientation`` and ``orientation_err`` attributes, properties,
and columns are `~astropy.units.Quantity` values in degrees, measured
counterclockwise from the positive x axis. The deprecated ``pa`` and
``pa_err`` attributes still return floats in radians until they are
removed.

An orientation given under the new name must carry
units. The ``orientation`` keyword and attribute of
`~photutils.isophote.EllipseGeometry` and the ``orientation``
keyword of `~photutils.isophote.EllipseSample` require an angular
`~astropy.units.Quantity`, and a number without units raises a
``TypeError``. A number without units is still accepted as radians
with the deprecated ``pa`` and ``position_angle`` keywords and
the deprecated ``pa`` attribute. Passing the orientation of
`~photutils.isophote.EllipseGeometry` as a positional number without
units is deprecated. The number is interpreted as radians, as before.
Code that passes the orientation positionally changes from::

    # Old (deprecated)
    geometry = EllipseGeometry(x0, y0, 20.0, 0.2, 0.5)

to::

    # New
    geometry = EllipseGeometry(x0, y0, 20.0, 0.2, 0.5 * u.rad)

The ``'main'`` and ``'all'`` values of the ``columns`` keyword of
`~photutils.isophote.IsophoteList.to_table` are deprecated. Use
``columns=None`` for the default columns and
``columns=isolist.properties`` for all of them. The
``IsophoteList.get_names`` method is deprecated in favor of the
``properties`` attribute.

.. _whatsnew-3.2-isophote-sigma-clip:

Isophote Sigma-Clipping Keywords
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The ``sclip`` and ``n_clip`` keywords of
`~photutils.isophote.Ellipse.fit_image`,
`~photutils.isophote.Ellipse.fit_isophote`, and
`~photutils.isophote.EllipseSample` are deprecated and will be removed
in version 4.0. Use the new ``sigma_clip`` keyword instead. The
``nclip`` keyword, which was deprecated in version 3.0, also points to
``sigma_clip`` now. The deprecated keywords clip around the mean, and
they clip only if the number of iterations is set. Code that uses them
changes from::

    # Old (deprecated)
    isolist = ellipse.fit_image(sclip=2.5, n_clip=3)

to::

    # New
    from astropy.stats import SigmaClip

    sigma_clip = SigmaClip(sigma=2.5, maxiters=3, cenfunc='mean',
                           stdfunc='std')
    isolist = ellipse.fit_image(sigma_clip=sigma_clip)

The ``cenfunc`` and ``stdfunc`` values reproduce the old behavior.
Without them, `~astropy.stats.SigmaClip` clips around the median,
which is more robust.

The ``sclip``, ``n_clip``, and ``nclip`` attributes
of `~photutils.isophote.EllipseSample` are deprecated
in favor of the new ``sigma_clip`` attribute. The
`~photutils.isophote.Ellipse.measure_isophotes` method is new in this
release, so it accepts only ``sigma_clip``.

Isophote Keywords With No Effect
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The ``maxgerr`` and ``going_inwards`` keywords of
`~photutils.isophote.Ellipse.fit_isophote` are deprecated
and will be removed in version 4.0. They have no effect. The
``max_gradient_rel_err`` criterion compares consecutive isophotes, so
it is applied only by `~photutils.isophote.Ellipse.fit_image`. The same
holds for the deprecated ``EllipseFitter.fit`` method.

The ``threshold`` keyword and the ``set_threshold`` method
of `~photutils.isophote.Ellipse` are also deprecated and
will be removed in version 4.0. They have no effect because
`~photutils.isophote.Ellipse` does not run the object centerer. Use
`~photutils.isophote.EllipseGeometry.find_center` to refine the initial
center before fitting.


.. _whatsnew-3.2-breaking-changes:

Breaking Changes
----------------

Source Position Columns in the PSF Tools
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

`~photutils.psf.PSFPhotometry` and
`~photutils.psf.IterativePSFPhotometry` now use the fitted columns of
an ``init_params`` table (e.g., ``x_fit``) before its initial columns
(e.g., ``x_init``). A table of previous results therefore restarts the
fit from its fitted values. Previously, it restarted the fit from its
initial values. A row with a nonfinite or masked fitted value uses its
initial values. To restart from the initial values, remove the fitted
columns from the table.

The x and y position columns of ``init_params`` and of the table
returned by the ``finder`` must now have the same suffix. Previously,
columns from different conventions (e.g., ``x_centroid`` and ``y_peak``)
were silently combined.

:func:`~photutils.psf.extract_stars` uses the same priority order.
A catalog with both ``x`` and ``y`` columns and a pair of fitted or
initial position columns now uses the fitted or initial positions,
unless the catalog has a ``skycoord`` column.

Isophote Missing Values
^^^^^^^^^^^^^^^^^^^^^^^

The `~photutils.isophote.Isophote` attributes that could not be
computed are now NaN instead of `None`. This applies to the gradient
errors, the higher-order harmonic amplitudes (``a3`` to ``b4``) and
their errors, the values and errors that are not defined for the
central pixel, and the geometry errors of isophotes whose geometry
was not fitted or that have too few data points. The gradient and the
higher-order harmonic amplitudes of the central pixel are zero, so that
it can be used to build model images. The columns of the tables from
`~photutils.isophote.IsophoteList.to_table` always have a numerical
data type. Code that tests these values with ``is None`` must use
`numpy.isnan` instead::

    # Old
    if isophote.a3 is None:
        ...

    # New
    if np.isnan(isophote.a3):
        ...

Isophote Semimajor Axis Limits
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The ``min_sma`` and ``max_sma`` limits of
`~photutils.isophote.Ellipse.fit_image` are now inclusive, as in
the STSDAS ``ellipse`` task. An isophote is fit at ``min_sma`` or
``max_sma`` if the semimajor axis reaches that value. Previously, such
an isophote was not fit. For example, a linear step of 5 pixels from
a starting semimajor axis length of 20 pixels with ``min_sma=10`` and
``max_sma=40`` now gives isophotes from 10 to 40 pixels instead of from
15 to 35 pixels.

`~photutils.isophote.Ellipse.fit_image` now raises a ``ValueError``
if ``min_sma`` or ``max_sma`` is NaN, if ``min_sma`` is larger than
``max_sma``, or if the starting semimajor axis length (``sma_start`` or
the ``sma`` of the input geometry) is not between them. Previously, the
starting isophote was fit even if it was outside the limits. To fit only
inward or only outward from the starting isophote, set ``max_sma`` or
``min_sma`` to the starting semimajor axis length.

`~photutils.isophote.EllipseGeometry`,
`~photutils.isophote.EllipseSample`, and
`~photutils.isophote.Ellipse.fit_isophote` now raise a ``ValueError`` if
the semimajor axis length is negative or not finite. A length of zero is
still allowed and gives the central pixel. Previously, ``fit_isophote``
returned the central pixel for a negative semimajor axis length, and a
NaN length raised an unclear ``AttributeError``.

Isophote Stop Codes
^^^^^^^^^^^^^^^^^^^

`~photutils.isophote.Ellipse.fit_isophote` now returns an isophote
with a stop code of 5, instead of -1, if no meaningful gradient could
be measured or the ellipse diverged. This is the stop code that
`~photutils.isophote.Ellipse.fit_image` already reported for such an
isophote, so the two codes had the same meaning. The stop code of -1 is
no longer used. Code that tests for it changes from::

    # Old
    if isophote.stop_code < 0:
        ...

to::

    # New
    if isophote.stop_code == 5:
        ...
